## Dictionaries

A **list** stores values in numbered slots (index 0, 1, 2, ...). Sometimes that is not the best choice. Sometimes you want to look up a value by a **name** instead of a number. A **dictionary** stores **key-value pairs**. Each value has a meaningful label.

Think of it like a real dictionary: you look up a **word** (the key) and get its **definition** (the value).

### Creating a dictionary

```python
process = {"pid": 1, "state": "ready", "priority": 3}
print(process)
```

Curly braces `{}` make a dictionary. Inside, each entry is written as `key: value`, separated by commas.

Here, `"pid"`, `"state"`, and `"priority"` are the **keys**. `1`, `"ready"`, and `3` are the **values**.

### Accessing values

Use square brackets with the **key** (not a number):

```python
process = {"pid": 1, "state": "ready", "priority": 3}
print(process["pid"])        # 1
print(process["state"])      # "ready"
print(process["priority"])   # 3
```

This is different from lists, where you use a number like `my_list[0]`. With dictionaries, you use the key name.

### Changing and adding values

Change a value by assigning to its key. Add a new key-value pair the same way:

```python
process = {"pid": 1, "state": "ready", "priority": 3}

# Change an existing value
process["state"] = "running"
print(process["state"])   # "running"

# Add a new key-value pair
process["time_left"] = 10
print(process)
```

If the key already exists, its value is updated. If it does not exist, a new entry is created.

### Checking if a key exists

Use `in` to check if a key is in the dictionary:

```python
process = {"pid": 1, "state": "ready"}

print("pid" in process)       # True
print("priority" in process)  # False
```

This is useful when you are not sure if a key has been added yet.

### Looping through a dictionary

You can loop through keys, values, or both:

```python
process = {"pid": 1, "state": "ready", "priority": 3}

# Loop through keys
for key in process:
    print(key)

# Loop through values
for value in process.values():
    print(value)

# Loop through both keys and values
for key, value in process.items():
    print(f"{key}: {value}")
```

The `.items()` method gives you both the key and the value on each step of the loop. This is the one you will use most often.

</Callout>

## Lists of dictionaries

You can combine lists and dictionaries to represent a collection of structured data. A **list of dictionaries** is like a table. Each dictionary is one row.

```python
process_table = [
    {"pid": 1, "state": "ready", "priority": 3},
    {"pid": 2, "state": "waiting", "priority": 1},
    {"pid": 3, "state": "ready", "priority": 2},
]

# Access the second process
print(process_table[1])

# Access the state of the second process
print(process_table[1]["state"])   # "waiting"
```

You use a number index to pick the dictionary from the list, then a key to pick the value from that dictionary.

### Looping through a list of dictionaries

```python
for process in process_table:
    print(f"PID {process['pid']}: {process['state']} (priority {process['priority']})")
```

This prints:

```
PID 1: ready (priority 3)
PID 2: waiting (priority 1)
PID 3: ready (priority 2)
```

## String methods

You already know how to index and slice strings (e.g. `text[0]`, `text[2:5]`). Now you will learn **string methods**. These are built-in tools that change a string or check it. You call them with a dot after the string.

### Splitting a string

`.split()` breaks a string into a **list** of smaller strings. By default, it splits on spaces:

```python
command = "LOAD R3 42"
parts = command.split()
print(parts)   # ["LOAD", "R3", "42"]
```

You can also split on a specific character:

```python
info = "P3:ready:5"
parts = info.split(":")
print(parts)   # ["P3", "ready", "5"]
```

This is useful for parsing structured text — like reading process information or commands.

### Joining a list into a string

`.join()` is the opposite of `.split()`. It takes a list of strings and joins them together with a separator:

```python
parts = ["PID", "1", "ready"]
result = " | ".join(parts)
print(result)   # "PID | 1 | ready"
```

The separator goes **before** the dot. Each item in the list is placed between copies of the separator. The list should contain strings.

### Cleaning strings

`.strip()` removes spaces (and newlines) from the start and end of a string:

```python
messy = "   hello   "
clean = messy.strip()
print(clean)       # "hello"
print(len(messy))  # 11
print(len(clean))  # 5
```

This is useful when reading user input, because people sometimes type extra spaces.

### Changing case

`.upper()` and `.lower()` convert a string to all uppercase or all lowercase:

```python
state = "Ready"
print(state.upper())   # "READY"
print(state.lower())   # "ready"
```

### Checking the start of a string

`.startswith()` returns `True` if a string begins with a given prefix:

```python
command = "LOAD R3 42"
print(command.startswith("LOAD"))    # True
print(command.startswith("STORE"))   # False
```

### Replacing text

`.replace()` swaps every occurrence of one piece of text with another:

```python
status = "state:waiting"
updated = status.replace("waiting", "ready")
print(updated)   # "state:ready"
```

## Building a process scheduler

Now let's put dictionaries, lists, and string methods together to build a **round-robin process scheduler**. This copies the idea from your OS lecture. The dispatcher gives each ready process a time slice, runs it for a short time, then switches to the next one.

<Callout tone="info" title="Lecture connection">

From your OS lecture:

- The **scheduler** maintains a process table — a list of all current processes with their states and priorities.
- The **dispatcher** picks a ready process, gives it a short burst of CPU time (a **time slice**), then saves its state and picks the next ready process. This is called **context switching**.
- In **round-robin** scheduling, the dispatcher cycles through all ready processes in order, giving each the same time slice. This is fair — every process gets equal CPU time.

Our simulator will model this cycle step by step.

</Callout>

### Step 1: define processes

Each process is a dictionary with a PID, a state, and a `time_needed` value (how many more time units it needs to finish).

```python
def create_process(pid, time_needed):
    return {
        "pid": pid,
        "state": "ready",
        "time_needed": time_needed,
    }
```

### Step 2: set up the process table

```python
process_table = [
    create_process(1, 4),
    create_process(2, 3),
    create_process(3, 5),
]
```

This creates three processes. Process 1 needs 4 time units, process 2 needs 3, and process 3 needs 5.

### Step 3: display the process table

Let's write a helper to show the state of all processes:

```python
def show_table(process_table):
    print(f"{'PID':<6}{'State':<12}{'Time left':<10}")
    print("-" * 28)
    for p in process_table:
        print(f"{p['pid']:<6}{p['state']:<12}{p['time_needed']:<10}")
    print()
```

The final `print()` makes a blank line after the table. The `:<6` in the f-string means "left-align and use at least 6 characters of space". This lines up the columns neatly.

### Step 4: the dispatcher (round-robin loop)

This is the core of the simulator. The dispatcher repeats these steps:

1. Find all ready processes.
2. If none are left, stop.
3. Pick the next one in order.
4. Set its state to `"running"` and give it one time slice.
5. Reduce its `time_needed` by the time slice amount.
6. If it has finished (time_needed reaches 0), set its state to `"finished"`. Otherwise, set it back to `"ready"`.

```python
def run_scheduler(process_table, time_slice):
    tick = 0

    while True:
        # Find all ready processes
        ready = []
        for p in process_table:
            if p["state"] == "ready":
                ready.append(p)

        # If no processes are ready, we are done
        if len(ready) == 0:
            print("All processes finished.")
            break

        # Pick the next ready process
        current = ready[tick % len(ready)]

        # Context switch: set it to running
        current["state"] = "running"
        print(f"Tick {tick}: Running PID {current['pid']} (time left: {current['time_needed']})")

        # Use the time slice
        current["time_needed"] = current["time_needed"] - time_slice

        # Check if the process is done
        if current["time_needed"] <= 0:
            current["time_needed"] = 0
            current["state"] = "finished"
            print(f"         PID {current['pid']} finished!")
        else:
            current["state"] = "ready"

        show_table(process_table)
        tick = tick + 1
```

Here is what each part does:

- **Ready list:** We loop through the process table and collect every process whose state is `"ready"`. This is the pool the dispatcher picks from.
- **Stopping condition:** If the ready list is empty, all processes have finished.
- **Round-robin selection:** `tick % len(ready)` cycles through the ready list. The `%` (modulo) operator wraps around: if there are 3 ready processes, `tick % 3` gives 0, 1, 2, 0, 1, 2, ...
- **Context switch:** We change the process state to `"running"`, simulate work by reducing `time_needed`, then decide if it is finished or should go back to `"ready"`. If a process finishes, we set `time_needed` to `0` so the table does not show negative time left.

### Step 5: run it

```python
process_table = [
    create_process(1, 4),
    create_process(2, 3),
    create_process(3, 5),
]

print("Initial state:")
show_table(process_table)

run_scheduler(process_table, time_slice=2)
```

When you run this, you will see the dispatcher move through the processes in order. Each one gets a time slice of 2. When a process runs out of time, it is marked as finished.
